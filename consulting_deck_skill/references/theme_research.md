# 三套咨询 reading deck 配色设计评审建议

日期：2026-09-05。角色：独立信息可视化设计评审代理（AI），并非外部真人设计师或三家公司授权设计师。

## 设计判断

真实需求是“选一种品牌气质后，所有证据、图表、表格和状态仍保持一致语义”，而不是三个主色的替换按钮。主题应当同时控制结构色、强调色、实体登记、量值色阶、数学偏差、经营状态、表格底纹和反白文字。三套主题共享语义接口，各自拥有完整色值；切换不改变结论和实体身份。

McKinsey 作为缺省项合理，但需在需求澄清阶段询问一次，合并进已有 brief，不要增加单独审批流程。用户已指定时不重复询问；用户回答“默认”、跳过选项或明确要求直接生成时采用 McKinsey；已经完成的项目应继承主题，除非用户要求切换。记录选择依据与最终 theme_id，避免之后重新推断。

## 调研证据与适配边界

1. **McKinsey 官方历史设计系统**：[MDS v0.9.1，2020，第3页](https://cdn.mckinsey.com/assets/sketch/McK_DS_core_Artboards.pdf)。明确列出 deep blue `#051C2C`、electric blue `#2251FF`、cyan `#00A9F4`；品牌色与功能数据色分别列出。这是历史 web 设计系统，不能冒称当前官方 PPT 规范。本项目采用前两种已核对 HEX，其余角色是本项目适配。
2. **McKinsey 官方身份说明**：[2019 新视觉身份](https://www.mckinsey.com/about-us/new-at-mckinsey-blog/the-new-mckinsey-look-gets-a-red-dot)与其设计合作方 [Wolff Olins 项目页](https://www.wolffolins.com/work/mckinsey)支持深蓝、白底、高对比的方向；不能由此推导所有页面必须蓝色或套用专有字体。
3. **BCG 真实公开 deck**：[India Economic Monitor, Jan 2026](https://web-assets.bcg.com/69/88/295258b24798bfb90f940d99057b/iem-jan26.pdf)，已下载并检查 PDF 第3页。观察：绿色判断标题、绿色模块名与表头、浅灰页面/白色内容区、高密度四象限表格；增长单元格另用色阶。本项目借鉴结构层级，但不照搬过亮底色上低对比小字，也不把增长无条件解释成经营利好。**下述 BCG HEX 是本项目设计选择，未声称官方色码**。本地证据：项目迭代记录中的 `iteration_v3_color/research/bcg-3.png`。
4. **Accenture 真实公开报告**：[Coloring Outside the Lines](https://www.accenture.com/content/dam/accenture/final/accenture-com/document/Accenture-Coloring-Outside-the-Lines.pdf)，已下载检查 PDF 第6页。观察：分析内容可使用白底、黑色正文和紫色结论，渐变仅在页边；不是必须通篇暗底。下述紫色系统为本项目设计选择，不冒称官方完整色板。本地证据：项目迭代记录中的 `iteration_v3_color/research/accenture-6.png`。
5. [Accenture 官方品牌发布说明，2020](https://newsroom.accenture.com/news/2020/change-powers-accentures-biggest-brand-move-in-a-decade)说明“>”在品牌中的角色；本技能只借鉴颜色，不添加第三方公司标志、商标或装成官方出品。

本轮没有取得 BCG/Accenture 的可公开核验完整官方色板；采用“品牌风格启发的独立预设”这一准确描述。

### McKinsey

深蓝负责标题、关键总计和结构边界；电蓝负责本页关键论据。分类图不使用六级蓝表示六家企业，否则用户容易误认为有顺序。青色只能用于大图形/非文字辅助强调；白字放青色上不能默认可读。

### BCG

绿色首先代表主题结构，因此 favorable 特意采用深蓝，加“达标/改善/✓”文字或符号。深蓝也出现在实体色时，状态必须是独立标签/状态列，不和实体填充混成一个图例。品牌绿不代表盈利、增长不代表好；经营评价须有指标口径，成本增长尤其不能自动绿色。

亮绿 `#21BA45` 对白只有约2.57:1，禁止白色小字叠放、禁止用作白底正文；该色只可作为有深色标签的大形状填充或边缘点缀，重要形状需要加深色边界。重点数据优先用深绿 accent。

### Accenture

以深紫结构、白底和局部紫色强调形成识别，避免紫、粉、蓝渐变覆盖所有数据。紫色不等于“未来/AI/高优先级”，除非显式登记。连续量必须是单调明度紫色阶，分类图采用离散色板；不使用彩虹或按类别逐项渐变。深色章节页可以存在，但分析页保持白底，分页切换不能改变实体色。

## 三套共同原则

- **先语义后装饰**：品牌/结构、实体类别、连续量、数学方向和经营评价是五种不同问题。同一填充在同一个图中只承载一种语义。
- **实体登记跨页保持稳定**：主题切换按类别索引重映射同一实体；图上重点通过描边/箭头/标签表达，不给被关注的实体临时换色。
- **默认不使用暗底或渐变**：分析页是白底；深色限封面/分节页，渐变不进入绘图区、数值编码区或文字底。真实公开 deck 使用过的效果不等于本技能必须照搬。
- **表格底色可解释**：结构表头 brand+白字；交替行 surface+ink；强调列 accent-soft+ink；热力表格才使用数值色阶。缺失数据用“—/未披露”和专用空值纹理，不伪装成最低值。
- **色阶图例完整**：顺序量说明上下限、单位；偏差说明中心、正负方向和区间；统计的“正”不自动映射 favorable。
- **色不能是唯一编码**：类别提供直接标签/线型，偏差提供 +/-，状态给文字与符号。六类别仍分不清时先用分面/排序/合并尾项；不无限扩展颜色。
- **打印适配**：对灰度相似的类别不用颜色硬分；转为线型、标记、直接标签或分面。截图通过不等于灰度通过。浅色连续量边缘可加 border，防止最低档和白底丢失。
- **反白文字显式计算**：brand/accent 可用已验证 on-brand/on-accent；类别和色阶应按真实填充计算，亮底深字、暗底白字，不假设“图形有颜色就能放白字”。透明叠加后的实际背景也要计算。

以上三个 brand 对白文字对比分别约17.37、8.74、17.43；accent 对白约5.69、5.37、8.34。计算为标准 sRGB 相对亮度比，仅覆盖这些纯色文字组合，不构成整体色盲可达性认证。

## 实现与验收要求

1. 统一 theme 注册表作为单一来源，CSS、SVG、ECharts、模板样例都读取同一主题；JSON/JS/CSS若复制色值，必须生成而不是人工维护多套。
2. theme_id 固定 `mckinsey`、`bcg`、`accenture`；缺失值默认 McKinsey，非法非空值应报错，不能静默退回导致用户以为已选中。
3. 持久化主题选择、语义映射、实体登记和来源边界；切换主题重生成相关产物，不把旧截图当新主题。
4. 用同一份数据、同一布局生成三套对照，至少包含分类柱图/连续热力表/正负瀑布/经营状态/信息图/表格，而不是只有三张封面。
5. 检查真实 SVG fill/stroke、ECharts color/visualMap、打印输出；扫除主题路径中写死旧色与 old pos/neg 误用。
6. 保留一页高密度分析页和一张对照色板，检查白底、反白、灰度与不依赖颜色识别；不能以“换色成功”替代信息表达验收。

### 实现字段补全

`gray-1`：McKinsey `#445563` / BCG `#365448` / Accenture `#4B3D58`；`gray-2`对应 muted，`gray-3`对应 border，`gray-4`对应 surface。`selected`对应 accent-soft。经营状态浅底：good-bg 为 `#E8F2EC / #E7F0F8 / #E6F2F1`；risk-bg 均 `#F9E8EC`；caution-bg 均 `#FBF1DC`；neutral-bg 等于 surface。浅底与对应深色文字成对使用，浅底本身不替代状态文字。
