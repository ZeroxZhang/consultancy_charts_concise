# 问题结构、假设与推理 · v6

本文件服务S1/S2的思考；S3叙事见 [storyline_method.md](storyline_method.md)，方法选用见 [framework_router.md](framework_router.md)。图型B编号保留为表达参考，不能代替分析步骤。

## 问题结构决定分析任务

从受众需要理解或选择的问题开始，明确范围、时间、基准和约束。问题不清楚时先探索材料，再收敛议题；不要用一个熟悉框架重新定义用户的问题。

- **议题树**：分解“必须回答什么”，每个叶节点应能转成可执行任务；写清同层拆分依据，重要交叉依赖单列。
- **驱动树**：用恒等式描述数量关系，例如`利润=Σ销量×单位贡献−固定成本`。节点必须说明口径与运算符；恒等式不能证明影响路径的因果。
- **假设树**：列出同一现象的竞争解释、支持/推翻信号与证据缺口。结果可为支持、反驳、混合或未决。
- **决策树**：组织可选行动、条件/不确定事件及结果；决策节点与机会节点分开，概率缺依据就保留条件分支。

MECE用于检查重叠与遗漏，复杂系统允许显式交叉依赖，不能为画整齐树而假装独立。按决策影响与取证成本确定分析深度，不把80/20或每层分支数当硬配额。

## 研究顺序与表达顺序

研究可以从工作假设或探索性问题开始；提出初步答案的同时写出替代解释与改变答案的条件。研究任务是检验而非保护假设。

表达时将有依据的答案前置。计划中的模型、支持性资料的数量、顺畅的标题，都不能证明结论已成立。相关性、分组差异和会计贡献必须分别标明。

旧规则“框架为验证本页标题服务”改为：**方法服务问题的检验，标题服从分析结果。** 重要反证不能因为不支持标题而被删除或仅藏入附录。

## 推理链的最小检查

`事实 → 分析结果 → 解释及替代解释 → 对问题的含义 → 条件性建议/下一步`

逐步问：
1. 事实口径一致吗，计算能复算吗？
2. 分析证明了什么，尚未证明什么？
3. 相反材料会怎样改变解释？
4. 建议需要的成本、现金、能力、时限依据在哪？
5. 若未知暂时无法解决，最有价值的下一步验证是什么？

例如“商超收入贡献了主要降幅”是会计拆解；“产品没有问题”需要客户、份额等额外证据；“转向电商可以扭转利润”还需要单位经济性、迁移与执行分析。

## 章节顺序

时间顺序适合进展；结构顺序适合范围分解；重要性顺序适合摘要；演绎适合共享前提下的推导；归纳适合多份互补证据的综合。没有一种顺序在所有任务中最强，SCQA也不等于完整演绎证明。
