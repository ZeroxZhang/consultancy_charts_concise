# 参考 02 · 逻辑框架与思维方式

> 来源：模块 2。本文件只写"思维层"；"画法层"（视觉规范/HTML 实现）在 chart_cards.md，
> 本文件以 [B-xx] 引用，不重复描述。

## 1. 先有框架、后有页面

**Deck 的结构 = 问题的结构。** 思考自下而上（从事实归纳）、表达自上而下（先给结论）。
页面顺序不是设计出来的，是论证出来的。违反的典型症状：写到第 20 页发现缺论点、整本返工——
这正是 ghost deck 要前置解决的问题。

## 2. 假设驱动（hypothesis-driven）

先提可证伪假设，再定向收集证据验证/推翻，而非穷举式数据分析（Rasiel，高置信）。
对 deck 的三条直接影响：
1. 页面顺序按"假设 → 证据"排布，每章先结论页、后证据页；
2. 每张图表只服务一个假设的验证——验证不了假设的图表进 appendix；
3. 假设被证伪是进度而非灾难：deck 如实呈现"我们原以为 X，数据显示 Y"（用对比页原型 [D-09]）。

反例：把 40 张图表按数据源顺序平铺——"数据游记"，不是论证。

## 3. MECE 与三种树

- **MECE**（不重不漏）：任意两分支无交集；全部分支合起来覆盖全集。
  与 80/20 联用：先列全（穷尽），再只深入决定性的 20%。
- **议题树**：问题分解为 MECE 子问题（定性）。画法 [B-36]。
- **驱动树/利润树**：议题树的数值化变体（利润=收入−成本→量×价−固定−变动），
  是瀑布/桥图 [B-09][B-10] 的思维底座。画法 [B-35]。
- **决策树**：决策工具而非页面工具——deck 只呈现决策路径的结论，不整棵上页。
- **四种逻辑顺序**（决定章节与页面排列）：
  - 时间顺序（步骤）→ 进展汇报；
  - 结构顺序（地理/组织/成分）→ 诊断报告常用；
  - 重要性顺序（排序）→ executive summary；
  - 演绎顺序（大前提→小前提→结论）→ 战略建议（SCQA）。
  **选错顺序是页面"读起来别扭"最常见的结构性原因。**

**最常见的框架误用（正反例）**：
- 错误：2×2 的轴选"好画但无战略含义"的维度（内部/外部×现在/未来）→ 四个没有行动含义的象限。
  修正：轴必须能推出"我们应该去哪格"——"市场增速×相对份额"直接推出四类资源动作。
- 错误：为显得结构化硬套框架，标题与框架无因果关系（五力包装竞对盘点）。
  修正：框架是为验证本页 action title 服务的（[E-05]）；标题不需要框架就不用。

## 5. 数据 → 分析 → 洞察 → 图表信息（三步链条）

1. **数据**：原始事实（"Q3 收入 42 亿"）；
2. **分析**：模式与比较（"同比 +12%，X 业务贡献 +10pct"）；
3. **洞察（so what）**：对决策者的含义（"增长质量取决于 X 的可持续性——需深挖 X 客户留存"）；
4. **图表信息**：把洞察压缩为一页一信息（对应 action title + 一组证据图）。

**只保留哪些数据**：一张图只保留支撑本页标题所需的数据；其余即使"已经做出来了"也进 appendix。
判断标准（so what 测试）：拿掉这张图标题还成立吗？成立→删除或降级。
反例：6 个部门全部 P&L 做成一张"全面但读不出结论"的报表页——数据倾倒页。
