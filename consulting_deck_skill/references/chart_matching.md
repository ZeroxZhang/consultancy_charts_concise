# 高密度信息的可视化路由 · v5

> v9适用原则：下列字段、编号、评分和布局预算用于复杂任务的按需参考，可合并或省略不影响结果的过程记录。分析/编码正确、核心内容可读完整与同版交付是底线；默认阈值和作者选择的区别见 [开放创作](open_authoring.md)。

适用于S1、S4和S5。目的不是从图表图库挑一个好看的样式，而是把原始数据或文本转成读者可以完成的比较、诊断和决策操作。

S1仅标记可用输入结构。原始资料需先按 [analysis_planning.md](analysis_planning.md) 完成S2分析；本路由从已得到的发现和证据进入，不能替代商业/财务方法选择。

表达路由顺序为：

`输入结构 → 可比性检查 → 读者操作 → 候选图型 → 页面组合 → 实现路径 → 容量回退`

阈值是1280×720 reading deck的起始预算，不是普遍定律。可以按实际媒介调整；重要取舍简记于已有笔记，并看原尺寸截图。

## 1. 先识别输入结构

不要直接把一批文件“摘要后画图”。先把能进入同一视觉编码的数据整理成下列输入结构；一个页面可以使用多个互补结构。

| 输入型 | 最少字段/关系 | 常见读者任务 | 优先候选 | 不满足时 |
|---|---|---|---|---|
| I-01 对象×指标明细 | 对象、指标、值、单位、期间、范围 | 查精确值、排名、找差距 | 比较表、排序条形、点图 | 单位/期间不同则分组表，不共用量尺 |
| I-02 时间序列 | 时间、系列、值、单位、事实/预测 | 看趋势、拐点、领先落后 | 折线、柱、小倍数、指数化 | 时间口径断裂则分段，不连线 |
| I-03 两期/两组配对 | 对象、起点、终点、同一量尺 | 看差额或排名迁移 | 哑铃、坡度、区间图 | 对象无法配对则用两个排序表 |
| I-04 部分—整体 | 类别、分项、值、明确分母 | 看构成、总量和份额变化 | 堆积、100%堆积、Mekko、构成表 | 分母不同或未知则禁止画成100% |
| I-05 起止与贡献项 | 起点、终点、贡献项、闭合规则 | 解释变化来源 | 瀑布/桥图、驱动验证表 | 不闭合时显式列缺口，不编“其他” |
| I-06 原始观测/样本 | 每条观测、分组、测量值 | 看分布、偏态、异常、区间 | 直方、箱线、点带、violin | 只有均值时不能伪造分布 |
| I-07 X×Y×Size | 对象、x、y，可选规模及同口径 | 看关系、象限、离群点 | 散点、气泡、2×2 | 两轴定性时用矩阵；规模单位不同不画气泡 |
| I-08 行×列矩阵 | 行对象、列维度、值或定义过的档级 | 扫模式、找热点、评估 | 热力、能力矩阵、Harvey表 | 精确查数优先表；档级无定义则先补定义 |
| I-09 节点—边—流量 | 节点ID、边、方向、可选权重 | 看流向、依赖、网络中心 | Sankey、network、关系图 | 无真实边时不用网络图 |
| I-10 层级/拆解 | 父子关系、同层拆分逻辑 | 看层级、驱动、议题拆解 | tree、驱动树、组织图 | 同层逻辑混杂时先重构分类 |
| I-11 任务—责任—时间 | 任务、责任人、阶段/日期、依赖、交付/门禁 | 看谁在何时交付什么 | 泳道、甘特、阶段门禁 | 没日期时用阶段，不伪造甘特长度 |
| I-12 地理记录 | 地区编码/经纬度、指标、时间 | 看空间分布与流向 | 地图、区域着色、map flow | 地理位置不影响判断时改排序条形 |
| I-13 编码后的文本证据 | 文本片段、主题码、对象、来源定位 | 看主题频次、共现、证据强弱 | 主题矩阵、条形+引文、共现网络 | 未系统编码时不能把摘录数量画成占比 |
| I-14 长文本论证材料 | 主张、证据、反证/边界、来源 | 看论证链、机制与缺口 | 证据台账、机制链、案例—边界矩阵 | 没有共同维度时保留结构化文字 |
| I-15 方案×标准 | 方案、标准、权重/定义、事实依据 | 做选择、看取舍 | 决策表、评分卡、敏感性图 | 权重和评分锚点不透明时不算总分 |

## 2. 再确定读者要完成的操作

同一数据可以服务不同结论。先写“读者看完后要比较/判断什么”，再选图。

| A编号与读者操作 | 主图/主展品 | 常见增强 | 典型回退 |
|---|---|---|---|
| A-01 查值 | 比较表、明细表 | 数据条、迷你趋势、来源定位 | 纯表格分页 |
| A-02 排名 | 水平条形、点图 | 基准线、Top/Bottom注释 | 对象太多转分组表 |
| A-03 看差距 | 哑铃、子弹、区间图 | 差额、相对差、目标线 | 基准不一致转证据表 |
| A-04 看趋势 | 折线、柱、小倍数 | CAGR、拐点、预测色带 | 多量纲转指数化或分面 |
| A-05 看构成 | 100%堆积、普通堆积、构成表 | 总量、份额、稳定系列顺序 | 小片多转完整表 |
| A-06 同看总量与构成 | 普通堆积、Mekko | 总量标签、份额表 | 只问份额时转100%堆积 |
| A-07 解释起止变化 | 瀑布、桥图 | 小计、连接线、净变化括号 | 贡献不闭合转缺口表 |
| A-08 看分布/不确定性 | 直方、箱线、violin、区间带 | 中位数、分位数、样本量 | 只有聚合值则改区间表 |
| A-09 看相关/定位 | 散点、气泡、2×2 | 参考线、象限、异常点 | 相关证据不足时不画因果箭头 |
| A-10 看流向/转化 | Sankey、漏斗、map flow | 流失节点、转化率、守恒校验 | 简单起止分解转瀑布 |
| A-11 看层级/驱动 | tree、驱动树、方程 | 数值、运算符、证据状态 | 只是并列主题则用分组表 |
| A-12 看过程/责任 | 阶段门禁、泳道、甘特 | 责任、交付、依赖、退出条件 | 无依赖的并列任务转行动表 |
| A-13 多标准评估 | 热力、Harvey、评分卡 | 档级定义、权重、敏感性 | 口径不齐转证据矩阵 |
| A-14 验证机制 | 机制链、因果假设图、driver-proof | 每条边的证据/反例、验证指标 | 只有概念时用“假设”清单 |
| A-15 比较案例/文本 | 对齐案例矩阵、paired cases | 原文短引、共同维度、边界 | 案例不可比时分组呈现 |
| A-16 做条件化决策 | decision table、组合矩阵、决策树 | 成立条件、经济性缺口、下一步 | 证据不足时输出待验证清单 |

## 3. 大量文本材料的转换规则

文本先结构化，再决定是否图示化。

| 文本中反复出现的结构 | 应抽取成 | 优先表达 | 禁止的捷径 |
|---|---|---|---|
| 多家公司/地区反复出现同类事实 | 对象×共同维度 | 对齐案例矩阵、比较表、小倍数 | 每家公司做一张独立卡片后声称可比 |
| “因为—所以—导致”语句 | 主体、动作、边、证据、替代解释 | 机制链+证据/反例行 | 把语言中的因果词直接画成已证实箭头 |
| 责任、动作、交付、条件 | 任务—角色—阶段—门禁 | 泳道或阶段门禁 | 只有时间顺序却画复杂网络 |
| 方案、优缺点、限制 | 方案×共同标准 | 决策表、评分卡 | 三列各写不同维度的长段落 |
| 高频主题或观点 | 主题码×对象×来源 | 主题矩阵、条形+代表引文 | 未定义编码过程就给“占比” |
| 主张、支持材料、反证、缺口 | claim—evidence—boundary | 证据台账、argument map | 用图标代替来源或证据强度 |
| 分类、子类、例子 | 父子层级 | 树、sunburst（数量型） | 非穷尽分类画成完整层级 |
| 不同材料没有共同维度 | 独立证据组 | 分组表或结构化文字 | 为了“有图”强行做雷达、流程或2×2 |

引文只保留能证明当前判断的最短片段，并保留来源定位。文本计数只有在语料范围、编码规则、重复处理和分母明确时才可进入统计图。

## 4. 高密度页面的组合方式

优先让多个展品共同完成一个证明责任，而不是把每张图孤立成一页。

| 页面组合 | 适用关系 | 推荐布局 | 失败信号 |
|---|---|---|---|
| 主比较 + 驱动验证 | 先证明差距，再解释来源 | benchmark-gap / driver-proof | 下半模块重复上图数字 |
| 总量 + 构成 | 同时回答规模与结构 | paired / driver-proof | 两图没有共同对象或期间 |
| 分布 + 代表案例 | 定量模式需要定性解释 | 主图2/3 + 案例/边界1/3 | 案例被当成总体证明 |
| 机制 + 证据/反例 | 因果仍需验证 | mechanism-chain + evidence row | 边没有证据状态或验证指标 |
| 概览 + 小倍数 | 总体模式与分组差异 | 上总览、下2–4分面 | 各分面量尺不同仍并排比较 |
| 表格 + 微型图 | 精确查值同时需要模式扫描 | evidence-table | 每列使用不同无说明的色阶 |
| 决策表 + 门禁 | 方案选择需绑定后续条件 | decision-table + decision strip | 推荐项没有成立条件和退出条件 |

### 起始容量预算

- 排序条形：正文通常8–15项，附录最多约24项；更多时分页或表格。
- 折线：正文通常不超过5条线；更多系列改小倍数。
- 热力：正文通常不超过约120–160格，且单元格文字仍需可读。
- 散点：超过15个点不默认全标签；只标关键点，必要时分面。
- 表格：不再用固定10行×7列作为绝对上限。先保证列单位、可比较维度和可读的数据文字（通常建议14px）；超页后按逻辑分组分页。
- 树/网络：节点越多越需要专门布局；一页无法看清关系时，输出总览+局部，而不是整体缩小。

## 5. 实现路径

复杂展品记录所选实现；简单页无需单独填render_route。更多自由实现见 [自定义展品](custom_exhibits.md)。

| 路径 | 适合 | 当前能力 | 选择理由 |
|---|---|---|---|
| `echarts-recipe` | 高频定量图 | rankedBar、groupedBar、timeSeries、composition、histogram、scatter、heatmap、sankey、tree | 有统一数据契约、主题、标签和SSR路径 |
| `echarts-native` | ECharts已有但尚未封装的统计/关系图 | boxplot、funnel、graph、map等 | 数据结构清晰，原生能力成熟 |
| `echarts-custom` | 坐标系内的专用几何 | range、violin、复杂甘特、成本曲线等 | 仍需要轴、缩放、图例与数据映射 |
| `exhibit-kit` | 构建时静态咨询展品 | waterfall、dumbbell、slope、bullet、Mekko等 | 打印稳定，含咨询特定校验和标签回退 |
| `html-css` | 精确表格与高文本密度结构 | comparisonTable、RACI、证据/决策矩阵 | 文字换行、列宽和分页更可控 |
| `svg-layout` | 战略屋、价值链、鱼骨等语义图 | 按页面生成并目视验收 | 几何和关系高度专用 |
| `elk-layout` | 复杂有向依赖图 | 按需引入 | 只有真实复杂网络才值得自动布线 |

ECharts能画不等于必须使用。表格、流程和文本型关系图如果转成ECharts后降低文字控制或增加运行时依赖，应保留HTML/SVG。

## 6. 候选选择与淘汰

已有合适选择时直接制作；有实质取舍时比较候选，不固定数量、不要求打分。判断参考：

1. **关系匹配**：几何是否直接表达读者操作；
2. **证据忠实**：是否保留单位、分母、范围、不确定性和缺失；
3. **密度收益**：是否减少查找和心算，而非只增加形状；
4. **标签适配**：真实中文/英文标签在分配区域能否完整呈现；
5. **受众成本**：目标读者是否能在短时间读懂；
6. **实现成熟度**：是否有已验证配方、静态输出和回退。

出现以下任一情况直接淘汰，不进入评分：

- 数据口径不可比却需要共轴、排序、相减或同色阶；
- 图型要求不存在的分母、层级、流量、日期、边或原始分布；
- 关键结论只能通过hover看到；
- 标签在目标媒介不可读且无法通过重排改善；
- 需要用手动移动数据点、伪造“其他”、把未知填0才能成立。

## 7. 复杂页的选型与规格参考

复杂展品可用下面的完整规格；普通页保留问题、关键来源和编码即可，无需所有字段或ID：

```yaml
question: 读者要完成什么比较或判断
input_shape: I-01..I-15
reader_operation: A-01..A-16
evidence_ids: [E01, E02]
comparability: 可比字段、口径差异与处理
candidates:
  - visual: 候选图型
    render_route: echarts-recipe|echarts-native|echarts-custom|exhibit-kit|html-css|svg-layout|elk-layout
    keep_or_reject: 保留/淘汰及理由
selected_visual: 最终图型或表格
recipe: 配方名或B编号
encoding: 字段到位置/长度/面积/颜色/线型
label_plan: 直接标签、图例、缺失值和长标签处理
density_plan: 项数、系列数、单元格/节点数与分配面积
fallback_trigger: 何时转表格、小倍数、总览+局部或拆页
```

丰富材料应主动探索多变量、机制和关系；图型由实际结构与读者任务支持，不由材料量本身决定。

## 8. 运行时回退与作者决策的分工

以上映射是作者的粗选型指引，不是关键词分类器或自动语义推荐算法。
`ChartRuntime.prepare`按给定配方、真实画布和字号预检；渲染后`check`读取实际字形位置，发现越界、文字重叠或小字号时转完整表格。不能因此跳过原尺寸目视。
运行时只自动处理保真表格/分页，不自动决定Top N、聚合、“其他”、抽样、因果解释或小倍数的业务分组；这些改变证明责任的操作要由作者写回`page_plan`。
硬输入上限仍可能直接报错；需要作者先分组或分页。表格行/列也放不下时明确拒绝，不能把报错视为已经完成回退。

可运行样例：`build_dense_reference.cjs`把1,152条合成明细聚合为趋势、全量排名与构成；把42段文本按显式人工编码转为6案例矩阵。候选淘汰理由、最终图/表和源证据ID在生成的`page_plan.json`中，不只藏在HTML里。
