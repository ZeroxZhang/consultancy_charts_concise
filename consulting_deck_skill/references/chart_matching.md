# 证据结构与deck视觉适配 · v9.2

> 本文件保留证据前提、既有I/A索引与deck制作约束。通用选型由 [planner协作入口](viz_planner_integration.md) 加载的独立技能维护；这里不另维护一套候选目录。编号与布局预算供复杂任务按需参考，开放创作规则不变。

适用于S1、S4和S5。目的不是从图表图库挑一个好看的样式，而是把原始数据或文本转成读者可以完成的比较、诊断和决策操作。

S1仅标记可用输入结构。原始资料需先按 [analysis_planning.md](analysis_planning.md) 完成S2分析；本路由从已得到的发现和证据进入，不能替代商业/财务方法选择。

表达路由顺序为：

`输入结构 → 可比性检查 → 读者要理解的关系 → 整页视觉构思／按需选型 → 实现与容量适配`

先按[整页创作](slide_anatomy.md)确定关系怎样在画布上展开；下面的输入索引和实现路径服务构思，不以组件种类决定页面结构。

阈值是1280×720 reading deck的起始预算，不是普遍定律。可以按实际媒介调整；重要取舍简记于已有笔记，并看原尺寸截图。

## 1. 先识别输入结构

不要直接把一批文件“摘要后画图”。先把能进入同一视觉编码的数据整理成下列输入结构；一个页面可以使用多个互补结构。

| 输入型 | 最少字段/关系 | 常见读者任务 | 不满足时 |
|---|---|---|---|
| I-01 对象×指标明细 | 对象、指标、值、单位、期间、范围 | 查精确值、排名、找差距 | 单位/期间不同则分组表，不共用量尺 |
| I-02 时间序列 | 时间、系列、值、单位、事实/预测 | 看趋势、拐点、领先落后 | 时间口径断裂则分段，不连线 |
| I-03 两期/两组配对 | 对象、起点、终点、同一量尺 | 看差额或排名迁移 | 对象无法配对则用两个排序表 |
| I-04 部分—整体 | 类别、分项、值、明确分母 | 看构成、总量和份额变化 | 分母不同或未知则禁止画成100% |
| I-05 起止与贡献项 | 起点、终点、贡献项、闭合规则 | 解释变化来源 | 不闭合时显式列缺口，不编“其他” |
| I-06 原始观测/样本 | 每条观测、分组、测量值 | 看分布、偏态、异常、区间 | 只有均值时不能伪造分布 |
| I-07 X×Y×Size | 对象、x、y，可选规模及同口径 | 看关系、象限、离群点 | 两轴定性时用矩阵；规模单位不同不画气泡 |
| I-08 行×列矩阵 | 行对象、列维度、值或定义过的档级 | 扫模式、找热点、评估 | 精确查数优先表；档级无定义则先补定义 |
| I-09 节点—边—流量 | 节点ID、边、方向、可选权重 | 看流向、依赖、网络中心 | 无真实边时不用网络图 |
| I-10 层级/拆解 | 父子关系、同层拆分逻辑 | 看层级、驱动、议题拆解 | 同层逻辑混杂时先重构分类 |
| I-11 任务—责任—时间 | 任务、责任人、阶段/日期、依赖、交付/门禁 | 看谁在何时交付什么 | 没日期时用阶段，不伪造甘特长度 |
| I-12 地理记录 | 地区编码/经纬度、指标、时间 | 看空间分布与流向 | 地理位置不影响判断时改排序条形 |
| I-13 编码后的文本证据 | 文本片段、主题码、对象、来源定位 | 看主题频次、共现、证据强弱 | 未系统编码时不能把摘录数量画成占比 |
| I-14 长文本论证材料 | 主张、证据、反证/边界、来源 | 看论证链、机制与缺口 | 没有共同维度时保留结构化文字 |
| I-15 方案×标准 | 方案、标准、权重/定义、事实依据 | 做选择、看取舍 | 权重和评分锚点不透明时不算总分 |

## 2. 读者操作索引

同一数据可以服务不同判断。把读者需要比较/理解的关系交给planner，已有明确选择可直接制作。A编号继续保留原含义：

| 编号 | 读者操作 | 编号 | 读者操作 |
|---|---|---|---|
| A-01 | 查值 | A-09 | 看相关/定位 |
| A-02 | 排名 | A-10 | 看流向/转化 |
| A-03 | 看差距 | A-11 | 看层级/驱动 |
| A-04 | 看趋势 | A-12 | 看过程/责任 |
| A-05 | 看构成 | A-13 | 多标准评估 |
| A-06 | 同看总量与构成 | A-14 | 验证机制 |
| A-07 | 解释起止变化 | A-15 | 比较案例/文本 |
| A-08 | 看分布/不确定性 | A-16 | 做条件化决策 |

编号不是必填字段；使用文字说明关系同样有效。planner结果需要继承此处的口径与证据状态，不能为了匹配某个图型反向改变输入含义。

## 3. 大量文本材料的转换规则

文本先结构化，再决定是否图示化。

| 文本中反复出现的结构 | 应抽取成 | 禁止的捷径 |
|---|---|---|
| 多家公司/地区反复出现同类事实 | 对象×共同维度 | 每家公司做一张独立卡片后声称可比 |
| “因为—所以—导致”语句 | 主体、动作、边、证据、替代解释 | 把语言中的因果词直接画成已证实箭头 |
| 责任、动作、交付、条件 | 任务—角色—阶段—门禁 | 只有时间顺序却画复杂网络 |
| 方案、优缺点、限制 | 方案×共同标准 | 三列各写不同维度的长段落 |
| 高频主题或观点 | 主题码×对象×来源 | 未定义编码过程就给“占比” |
| 主张、支持材料、反证、缺口 | claim—evidence—boundary | 用图标代替来源或证据强度 |
| 分类、子类、例子 | 父子层级 | 非穷尽分类画成完整层级 |
| 不同材料没有共同维度 | 独立证据组 | 为了“有图”强行做雷达、流程或2×2 |

引文只保留能证明当前判断的最短片段，并保留来源定位。文本计数只有在语料范围、编码规则、重复处理和分母明确时才可进入统计图。

## 4. 高密度页面的组合方式

优先让多个展品共同完成一个证明责任，而不是把每张图孤立成一页。

| 页面组合 | 适用关系 | 推荐布局 | 失败信号 |
|---|---|---|---|
| 主比较 + 驱动验证 | 先证明差距，再解释来源 | benchmark-gap / driver-proof | 下半模块重复上图数字 |
| 总量 + 构成 | 同时回答规模与结构 | paired / driver-proof | 两图没有共同对象或期间 |
| 分布 + 代表案例 | 定量模式需要定性解释 | 主图2/3 + 案例/边界1/3 | 案例被当成总体证明 |
| 机制 + 证据/反例 | 因果仍需验证 | mechanism-chain + evidence row | 边没有证据状态或验证指标 |
| 概览 + 小倍数 | 总体模式与分组差异 | 上总览、下2–4分面 | 各分面量尺不同仍并排比较 |
| 表格 + 微型图 | 精确查值同时需要模式扫描 | evidence-table | 每列使用不同无说明的色阶 |
| 决策表 + 门禁 | 方案选择需绑定后续条件 | decision-table + decision strip | 推荐项没有成立条件和退出条件 |

### 起始容量预算

- 排序条形：正文通常8–15项，附录最多约24项；更多时分页或表格。
- 折线：正文通常不超过5条线；更多系列改小倍数。
- 热力：正文通常不超过约120–160格，且单元格文字仍需可读。
- 散点：超过15个点不默认全标签；只标关键点，必要时分面。
- 表格：不再用固定10行×7列作为绝对上限。先保证列单位、可比较维度和可读的数据文字（通常建议14px）；超页后按逻辑分组分页。
- 树/网络：节点越多越需要专门布局；一页无法看清关系时，输出总览+局部，而不是整体缩小。

## 5. 实现路径

复杂展品记录所选实现；简单页无需单独填render_route。更多自由实现见 [自定义展品](custom_exhibits.md)。

| 路径 | 适合 | 当前能力 | 选择理由 |
|---|---|---|---|
| `echarts-recipe` | 高频定量图 | rankedBar、groupedBar、timeSeries、composition、histogram、scatter、heatmap、sankey、tree | 有统一数据契约、主题、标签和SSR路径 |
| `echarts-native` | ECharts已有但尚未封装的统计/关系图 | boxplot、funnel、graph、map等 | 数据结构清晰，原生能力成熟 |
| `echarts-custom` | 坐标系内的专用几何 | range、violin、复杂甘特、成本曲线等 | 仍需要轴、缩放、图例与数据映射 |
| `exhibit-kit` | 构建时静态咨询展品 | waterfall、dumbbell、slope、bullet、Mekko等 | 打印稳定，含咨询特定校验和标签回退 |
| `html-css` | 精确表格与高文本密度结构 | comparisonTable、RACI、证据/决策矩阵 | 文字换行、列宽和分页更可控 |
| `svg-layout` | 战略屋、价值链、鱼骨等语义图 | 按页面生成并目视验收 | 几何和关系高度专用 |
| `elk-layout` | 复杂有向依赖图 | 按需引入 | 只有真实复杂网络才值得自动布线 |

ECharts能画不等于必须使用。表格、流程和文本型关系图如果转成ECharts后降低文字控制或增加运行时依赖，应保留HTML/SVG。

## 6. 接回后的证据与媒介检查

候选召回与选型方法由planner执行；主会话检查返回方案能否承担本页证明责任。已有结果时复用其理由，不再填写一份候选表。重要调整简记原因即可。

下列客观问题必须处理，不能用“planner已返回ok”豁免：

- 数据口径不可比却需要共轴、排序、相减或同色阶；
- 图型要求不存在的分母、层级、流量、日期、边或原始分布；
- 关键结论只能通过hover看到；
- 标签在目标媒介不可读且无法通过重排改善；
- 需要手动移动定量数据点、伪造“其他”、把未知填0才能成立。

证据问题返回受影响分析；媒介问题调整实现、布局或分页。换用ExhibitKit、HTML/SVG等实现时，保持关系语义、关键比较和证据边界。

## 7. 复杂页的选型与规格参考

复杂展品可用下面的完整规格；普通页保留问题、关键来源和编码即可，无需所有字段或ID：

```yaml
question: 读者要完成什么比较或判断
input_shape: I-01..I-15
reader_operation: A-01..A-16
evidence_ids: [E01, E02]
comparability: 可比字段、口径差异与处理
planner_ref: 已采纳plan与模块引用（有委派时）
render_route: echarts-recipe|echarts-native|echarts-custom|exhibit-kit|html-css|svg-layout|elk-layout
author_adjustment: 重要调整及理由（有调整时）
selected_visual: 最终图型或表格
recipe: 配方名或B编号
encoding: 字段到位置/长度/面积/颜色/线型
label_plan: 直接标签、图例、缺失值和长标签处理
density_plan: 项数、系列数、单元格/节点数与分配面积
fallback_trigger: 何时转表格、小倍数、总览+局部或拆页
```

丰富材料应主动探索多变量、机制和关系；图型由实际结构与读者任务支持，不由材料量本身决定。

## 8. 运行时回退与作者决策的分工

本文件的结构索引帮助交接和制作，不能代替真实选型判断。
`ChartRuntime.prepare`按给定配方、真实画布和字号预检；渲染后`check`读取实际字形位置，发现越界、文字重叠或小字号时转完整表格。不能因此跳过原尺寸目视。
运行时只自动处理保真表格/分页，不自动决定Top N、聚合、“其他”、抽样、因果解释或小倍数的业务分组；这些改变证明责任的操作要由作者写回`page_plan`。
硬输入上限仍可能直接报错；需要作者先分组或分页。表格行/列也放不下时明确拒绝，不能把报错视为已经完成回退。

可运行样例：`build_dense_reference.cjs`把1,152条合成明细聚合为趋势、全量排名与构成；把42段文本按显式人工编码转为6案例矩阵。候选淘汰理由、最终图/表和源证据ID在生成的`page_plan.json`中，不只藏在HTML里。
