# 参考 01 · 叙述方法论（Storyline & Narrative）

> 来源：《咨询公司 Deck 制作手册 v2.0》模块 1。置信度口径：高＝官方/著作/已核验公开页面；
> 中＝可靠二手（前顾问渠道）；低＝三手或推断。

## 1. 金字塔原理在 deck 中的落地（Minto，高置信）

- **SCQA**：S 共识背景 → C 打破稳态的变化 → Q 需要回答的问题 → A 建议。
  Deck 开场 1–4 页（S、C 各一页，Q 一页或并入 C，A 进入 exec summary）。
  建议明确只需制造紧迫感时用 SCR（省 Q）。
  **检验**：S 必须是"客户点头无争议"的事实——客户不认 S，后面全部失效。
- **纵向逻辑**：每页标题必须被本页内容证明（标题=结论、图表=证据、要点=推理链）。
  检验：遮住标题看正文能反推出标题。
- **横向逻辑**：所有 action title 连读本身构成完整论证。
  检验：只读标题 30 秒讲完故事（电梯测试）。
- **归纳 vs 演绎**：演绎（大前提→小前提→结论）说服力最强但不可跳读——用于
  exec summary 与关键建议页；归纳（并列论据→共同结论）允许跳读、抗打断——用于诊断主体与进展汇报。

## 2. Storyline 开发流程（五步，按顺序）

1. **Answer first**：先写"我们建议客户做什么"（deck 的最后一页结论，流程的第一步）。
   检验：30 秒内能复述。
2. **Dot-dash storyline**：完整句论点（dot）+ 支撑句（dash）两级缩进的论证树，一页纸。
   检验：上层句子是下层的概括；每行过 so what 测试（"所以呢？"答不上来就删）。
3. **Ghost deck**：每页一个 action title + 一句"本页用什么图表/数据证明"。
   **在此刻呈现标题骨架；需要确认新方向时请用户确认，已有自主制作授权则记录并继续**——调整一行标题成本趋近于零，
   调整一张成稿图表成本是一个晚上。
4. **Storyboard**：每页手绘草图与布局分区——先定"几栏、图放哪、takeaway 放哪"。
   检验：每页一句话说出"这页证明什么、用什么证明"。
5. **一页一信息**：每页一个主判断 + 一组足够且不重复的证据（允许多图/表/机制图）。
   检验：删掉本页是否损失唯一信息？是→保留；否→合并或删页。

## 3. Action title（结论式标题）写法

**句式公式**：主体 + 变化/结论 + 量化证据（+ 影响）。动词优先，数字尽量入题。
- 英文：保留完整判断，按实际宽度控制在两行以内。
- 中文：按实际渲染控制最多两行，不能为凑字数删去必要限定。

| 描述型（反例） | 结论型（正例） |
|---|---|
| 2023 年收入情况 | 收入增长 12%，八成来自 X 业务 |
| 市场份额分析 | 高端市场领先 8 个百分点，中端被 A 公司反超 |
| 成本结构 | 物流成本高出行业均值 3 个百分点，是利润第一短板 |
| 下一步计划 | 三季度前完成 X 试点，可释放 2 亿潜在收入 |

**三者分工（禁止互相重复）**：
- 页面标题 = 结论（so what）；
- 图表标题（如保留）= 描述性（what，如"2019–2023 分业务收入"）；
- takeaway box = 该页对决策者的行动含义（now what，一句话）。

## 4. 章节骨架（按场景）

| 场景 | 骨架 | Exec summary | Appendix 策略 |
|---|---|---|---|
| 诊断报告 | SCQA → 现状（2–3 章）→ 根因 → 建议 → 实施计划 | 1 页独立成立：结论+3–5 关键证据数字+建议 | 分析细节、数据表、模型说明，正文引用编号 |
| 战略建议 | 决策请求 → 选项（2–3）→ 评估 → 推荐 → 实施路径 | 1–2 页：推荐+理由摘要+要客户做的决定 | 选项评估明细、敏感性分析 |
| 进展汇报 | 状态总览（RAG）→ 里程碑进展 → 风险与求助 → 下一步 | 1 页状态页（KPI 仪表板式） | 项目台账、明细里程碑 |
| 董事会材料 | 决策页前置；每页 1 个决策或 1 个关键事实 | 决策摘要页："今天要批准的事项" | 深度分析留作 pre-read 附件 |
| Proposal | 对问题的理解 → 方法 → 团队资历 → 时间定价 | 1 页"为什么选我们"三段式 | 案例库、团队简历 |
| 公开研究报告 | 章节式目录；章标题替代 action title | 要点页（Key findings） | 方法论、数据附录 |

**Exec summary 写法**：金字塔结构——每节一句加粗要点句 + 数字事实；
只读加粗部分能串成完整故事。反例：写成"项目过程复述"（我们做了什么、开了什么会）。

## 5. 呈现与讲述（delivery）

- **现场讲一张高密度图的四步顺序**（Knaflic SWD 与咨询惯例合并）：
  ① 结论（10–15 秒：这页要说什么）→ ② 坐标系（轴、单位、图例定义"语言"）→
  ③ 锚点数据（支撑结论的 2–3 个数字）→ ④ 回到结论 + 行动含义。
- **节奏**：每页 60–90 秒（内容页预算，非均匀配速）；30 页 ≈ 30–45 分钟。
  超时取舍：现场只讲标题 + 锚点数据 + takeaway，细节留给 appendix。
- **Reading deck vs Presentation deck 是两种产品**：

| | Reading deck（咨询主流） | Presentation deck（极简派） |
|---|---|---|
| 消费方式 | 会前读/会后查 | 现场听 |
| 信息密度 | 高：每页一个论证单元 | 低：每页一个观点单位 |
| 标题 | Action title（结论句） | 短标题或图主视觉 |
| 失败方式 | 读不出结论（密度失控） | 撑不住 90 分钟（信息不足） |

  用户需要两种媒介时可以提供**双版本**——完整版 pre-read + 降密度现场版
  （选讲 12–15 页 + 大图 + 只保留标题与锚点数据）。用户要现场版时从完整版裁剪。

## 6. 证据边界（必须遵守）

各公司内部模板/规范不公开；凡"公司内部规范"无法找到公开来源的，一律标注推断，
不冒充官方。做"某某公司风格"时用公开报告观察 + 前顾问渠道描述（模块 7 已提炼），
并在交付说明中如实告知。
