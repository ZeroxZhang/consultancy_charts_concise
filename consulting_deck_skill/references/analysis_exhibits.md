# 分析图表的表达语法 · v4

适用：S4 选型、S5 规格、S6 精加工、S7 验收。目标是让读者少心算、少查图例、少在图和文字之间往返。
think-cell 是能力参照；下述规则为本项目独立适配，不是官方模板或必须采用的外观。

## 先确定读者的操作

| 读者需要知道 | 优先表达 | 值得增加的细节 | 应退回简单表达的情况 |
|---|---|---|---|
| 谁大、差多少 | 排序条形 / 点图 / 哑铃 | 直接数值、同量尺、差额或目标线 | 数据口径不同：分组证据表 |
| 从起点如何到终点 | 瀑布 / 贡献桥 | 小计、连接线、起止净变化括号 | 贡献不闭合：列缺口，不编一个“其他” |
| 总量和构成怎样变化 | 普通堆积 + 总量；份额任务用100%堆积 | 柱上总量、段内原值/份额、稳定系列顺序 | 精细比较非基底系列：拆成小倍数/点图 |
| 各市场大小与内部结构 | 百分轴Mekko | 列宽=总量、段高=份额、面积=绝对量 | 只关心份额：100%堆积；窄片多：表格 |
| 同时核对多个精确指标 | 比较表 | 列头单位、数值对齐、差异列、必要数据条 | 不同单位不得混用一条量尺；不要把每列都染成热力图 |
| 谁在何时交付、何种条件进入下一步 | 泳道 / 阶段门禁 / 甘特 | 责任、交付、条件、已知依赖 | 并列主题无顺序：用分组表，不强加箭头 |
| 机制如何拆解 | 驱动树 / 方程 / 关系图 | 节点角色、运算符、关系含义 | 缺因果证据：标假设；只列概念时用清单 |

先写图回答的问题，再决定是否增加复杂度。普通条形、纯表格与简短文字都可能是最终最优解。
不设 think-cell 风格覆盖率、复杂图数量或全篇统一括号/箭头配额。

## 视觉语法

- 用基线、对齐、分组间距表达结构；大面积底色、卡片和粗框仅在确有分组/状态含义时使用。
- 直接标签靠近图形；总量、分项、差额各有位置。单位通常放图头，避免每个数重复长单位。
- 参考线写业务含义；差异括号只连接实际比较的端点。箭头的方向不能暗示不存在的因果。
- 同实体沿用主题中的同一类别色。数学增减使用 delta 角色，好坏由经营含义判断。
- 有直接数值时可弱化冗余网格；零基线、必要尺度和分母仍保留。
- 堆积和Mekko按系列稳定排序；不为更均匀的色块移动数据或给零值虚构最小面积。
- 图表内已把比较讲清时，可采用 `.reading.analytical` 减弱外围说明框；普通 reading 样式仍可用。

## 注释计算契约

| 类型 | 计算 | 前提 |
|---|---|---|
| absolute | end − start | 相同单位、期间含义、范围 |
| relative | (end − start) / start × 100% | start > 0；零/负基数改报绝对差并解释 |
| pp | end − start | 显式声明百分数输入是0–1的fraction，还是0–100的percent |
| cagr | ((end / start)^(1 / years) − 1) × 100% | 正起止值，实际年数；3个年度观测通常是2个间隔 |

组件只验证数值，作者仍需验证口径可比。不得用数组长度替代实际年数，不把百分点标成增长率。
先用原值计算，最后格式化；不为让显示比例“凑到100%”偷偷改原值。必要时注释舍入误差。
`difference` 对不适用输入报错。表格中缺失输入显示“—”；业务上不适用的比率应移除计算列，或明确写文字说明。

## 标签与密度的回退顺序

1. 为标题、刻度、图内标签、差异标注、完整数据表分别分配空间。
2. 标签可移动，数据点/柱长/段面积不可移动。缩写必须可理解或有对应全称。
3. Mekko/堆积段放不下名称和数值时，自动转为同图下方完整数据表，列用序号关联；不静默漏掉小片。
4. 图和表仍放不下，或相邻窄列连序号都无法区分时，扩大模块或直接改表；组件报错是需要改规格的信号，不用缩小viewBox绕过。
5. 组件估宽只作提前判断；最终字号、中文、长英文、窄列仍以原尺寸浏览器截图和PDF为准。

## 图示、表格与信息图

表格先区分标识列、原值列、计算列和解释列。数字右对齐；一列一种单位；总计由作者提供，不自动相加比率。
数据条必须有包含零的统一domain，列头显示量尺；未知值与零分开。文本较长时允许换行，必要时分页。
流程的等宽阶段表示顺序，不表示等时长；没有明确日期时用阶段，不伪造甘特时间轴。
阶段门禁用责任/交付/放行条件的对齐行组织；分支、反馈或跨部门依赖改用泳道/专门关系图。
信息图应由“关系 + 数据/机制 + 必要解释”构成。图标只有在帮助识别对象时使用，不能取代证据。

## 可执行能力与例子

API和运行方式见 `exhibit_system.md`；示例见 `assets/analysis_reference_deck.html`，可用
`node scripts/build_analysis_reference.cjs` 重建。六页涵盖同数据对照和应当保留普通表格的反例。
新增数值与输入边界测试：`node scripts/test_analysis_exhibits.cjs`。

当前支持单段瀑布、普通/100%堆积、百分轴Mekko、比较表、线性阶段流程；未实现堆积瀑布、单位轴Mekko、任意标签自动避让或任意网络路由。
不复制 think-cell 编辑器、PowerPoint/Excel 联动或可编辑PPTX功能。

## 官方参照与适配边界

以下网页已于2026-09-05打开核验；只提炼机制，代码和样稿为原创。

- [Chart annotations](https://www.think-cell.com/en/resources/manual/chartdecorations)：差异、CAGR、参考线和连接线能绑定数据更新。本项目采用数据派生注释，但不照搬其日期日数算法。
- [Chart labels](https://www.think-cell.com/en/resources/manual/textlabels)：标签布局是独立功能。本项目仅有保守估宽和完整表格回退，不声称同等自动避让能力。
- [Mekko](https://www.think-cell.com/en/resources/manual/mekko)：区分百分轴与单位轴。现有kit仅支持前者。
- [Tables](https://www.think-cell.com/en/resources/manual/table) 与 [Process flows](https://www.think-cell.com/en/resources/manual/processflow)：表格和流程也是表达工具；本项目根据阅读任务设计组件。
- [Style files](https://www.think-cell.com/en/resources/manual/style-files)：外观可配置，故沿用本项目三套主题，不新增“think-cell配色”。
