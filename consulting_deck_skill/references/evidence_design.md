# 证据架构与信息密度

## 证据契约

`evidence.json` 为对象数组，每项至少包含：
```json
{"id":"E01","claim":"某公司海外收入增长","value":12.3,"unit":"亿元",
 "period":"2025FY","scope":"合并海外业务","denominator":null,
 "source":{"title":"公司年报","url":"实际来源链接","locator":"页码/表名"},
 "status":"verified","retrieved":"YYYY-MM-DD","formula":null,
 "limitations":"收入不等同出口；不代表行业"}
```
status 区分 verified / user-provided / unverified / derived / estimate / synthetic。
verified 必须打开原始来源且找到对应数字；摘要命中只能是unverified。
derived 必须给输入ID和公式；estimate 必须给假设与区间；synthetic明确虚构。
没有可靠来源时保留null与缺口，禁止填“合理数值”。

## 页面规格契约

```yaml
page: P08
mode: reading
claim: 不同出海业务的增长信号提示分层研究，尚不足以直接排投资优先级
evidence_ids: [E01, E02, E03]
proof_obligation: 分别展示公司样本和行业指标，并明确比较边界
modules:
  - id: M1
    question: 行业量值与增速如何变化
    evidence_ids: [E01, E02]
    visual: 带数值条的比较表
    encoding: 每行单位单列；增速条只在同口径组内共享轴
    area: {columns: "1 / 9", rows: "1 / 2"}
  - id: M2
    question: 哪些证据还不足以形成投资建议
    evidence_ids: [E03]
    visual: 证据缺口表
    area: {columns: "9 / 13", rows: "1 / 2"}
reading_order: [M1, M2]
interpretation: 增速筛选需再核实利润、资本占用、准入条件
limits: 公司数据不能推断赛道规模；不同期间不做排名
```

## 密度预算（项目默认建议，非MBB官方标准）

| 场景 | 起始预算 | 可读性验收 |
|---|---|---|
| reading/pre-read | 2–4个相互补充的证据模块；可为一张完整大表/图 | 标题10秒可扫、1分钟能复述证据链、关键标签无需放大 |
| presentation | 1–2个核心证据，大字、现场动线 | 实际投影距离验证；不足时减密度 |
| 执行摘要 | 3–5条判断，各有证据与对应页号 | 扫读判断列能知道应决策什么 |
| 附录 | 数据与方法完整，不强限表格行数 | 仍不能截字或依赖hover；长表合理分页 |

数字、事实、机制、比较、限定条件是有效信息；复述标题的bullet不是新增证据。
密度不等于非白像素比例：加背景可轻易作弊，故面积测量只作诊断提示。
连续两页同样两栏不是自动失败，但需要检查两页是否真有相同的论证关系。

## 证据补强顺序

1. 增加同口径基准（历史/竞品/目标）；2. 分解总量驱动；3. 检查分布与反例；
4. 增加机制、可执行条件和边界；5. 不足则收窄判断或合页。
不能为凑密度引入无关调查或将单案例结果称为“成功公式被证明”。

## 数据几何契约

- 百分比同比与百分点差分别计算，不同分母不能相减。
- 半年与全年不连成连续趋势；保留分区或做同期比较。
- 气泡面积编码：r=k√value，有单位、尺度图例和来源；跨单位规模不能共用面积编码。
- 定性轴使用低/中/高或有定义的等级；没有量化数据就不画百分比刻度。
- 线性轴坐标必须由同一公式计算；不得手动挪动点“改善布局”，移动的是标签和引导线。
- 桑基需流量守恒或显式流失节点；Mekko列宽按总量、段高按列内份额；网络箭头注明关系。
