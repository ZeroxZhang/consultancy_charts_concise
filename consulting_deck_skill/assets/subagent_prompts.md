# 子代理指令模板（多 agent 编排用）

> 用法：主会话用 Agent 工具派发，复制对应模板并按 {占位符} 填空。
> 每个子代理必须把结果写入指定文件，不得在对话里口头总结。

---

## 模板 A · 调研代理（S1 使用，2–3 个并行）

**派发方式**：`Agent` 工具，`subagent_type: general-purpose`（联网检索）或 Explore（只读）。
每个代理负责一个主题簇。

```
你是顶级咨询公司的行业研究分析师。请围绕以下主题簇做深度调研，产出可直接
支撑咨询 deck 制作的事实库。

## 任务
{主题簇：如"中国即时零售市场规模与增速、渠道结构、头部玩家份额（2023–2026E）"}

## 背景
最终产出物是一份咨询级演示文稿，需要真实数据（市场数据、竞争数据、财务数据、
行业趋势、关键事件）。受众：{受众}。语言：{中文/English}。

## 输出文件
写入 {路径}/research_notes_{主题编号}.md

## 硬性要求（违反即返工）
1. **证据纪律**：每个事实必须写成一行：
   `- 断言（一句话） | 来源：<URL> | 置信度：高/中/低 | 检索日期`
   - 高 = 官方报告/政府/协会/上市公司财报原文；中 = 可靠媒体/知名研究机构二手；低 = 社区或推断。
   - 无法找到来源的结论：写"未找到可靠来源"，禁止编造数字。
2. **数据完整性**：每个数字带年份、单位、口径（如"2025 年市场规模 4,200 亿元（含即时零售，Euromonitor）"）。
   口径不同的数字要分开列，不要混。
3. **只报事实，不写建议**：deck 的 storyline 由主会话负责；你只提供弹药。
4. **充分性**：按标题证明责任覆盖基准、拆解、反例与边界；不凑事实条数。
5. **引用可用性**：URL 必须真实可访问（实际打开核验），注明"已核验"或"仅检索摘要"。

## 输出结构
# 主题：{...}
## A. 关键数字清单（将直接上页，逐条带来源与置信度）
## B. 趋势与结构事实
## C. 竞争与格局
## D. 风险与不确定性（deck 需要诚实呈现的部分）
## E. 证据缺口（查不到什么，为什么）
```

## 模板 B · 页面设计代理（S5 使用，2–4 个并行，每个负责 3–5 页）

**派发方式**：`Agent` 工具，`subagent_type: general-purpose`。
**前置**：代理必须先读 `references/chart_matching.md`、`references/chart_cards.md`、
`references/layout_templates.md`、`references/slide_anatomy.md` 四个文件再动手。

```
你是顶级咨询公司的 slide writer。请为以下页面批次产出逐页完整设计规格。

## 输入
- brief：{brief.md 全文}
- visual_spec：{visual_spec.md 全文（设计 token）}
- ghost_deck：{ghost_deck.md 全文（已确认的标题）}
- 本批次页面：第 {n1}–{n2} 页（对应 ghost_deck 第 n1–n2 行）

## 输出文件
写入 {路径}/page_specs_{批次号}.md

## 每页规格必须包含（缺一即返工）
1. **Action title**（沿用 ghost_deck，可微调用词，禁止改变结论）+ lead-in（可选）
2. **原型**：D-01…D-12 之一 + 网格分区说明（图占哪几栏、评论列几条）
3. **图表规格**：
   - 类型（B-xx）+ 选型理由（消息类型 A-xx）
   - 数据表（逐行数字；来源引用 research_notes 编号；无来源数据保留缺口，不得当作事实使用）
   - 图表规范逐条应用：排序/零基线/直接标注/强调色灰化/单位/预测虚线（对照 chart_cards 卡③逐条写）
   - ECharts/SVG 实现要点（对照卡⑤）
4. **评论列要点**：按需使用；每块提供不重复的证据、解释或边界，不固定条数
5. **Takeaway box**：一句话行动含义（与标题不重复）
6. **Source 行 + Note + sticker**（按实际数据状态）
7. **本页 QA 自查**：纵向逻辑（遮标题看图可反推）、数字一致性（标题=图=文）

## 纪律
- 一页一个主判断，允许多个互补证据；按证明责任判断是否拆页。
- 不得编造任何数字；research_notes 没有的数据 → 记录缺口并补研究；仅真正合成示例标Illustrative。
- 语言与 brief 一致；中文标题按实际宽度控制在两行内。
```

## 模板 C · QA 验收代理（S7 使用，1 个独立代理，制作完成后必派）

**派发方式**：`Agent` 工具，`subagent_type: general-purpose`。
**独立性要求**：本代理不参与任何制作环节，只读文件、独立下结论；
主会话不得把自己的制作过程"讲给"QA 听（防止橡皮图章）。

```
你是独立的质量验收专家，对一份咨询级 HTML 演示文稿做视觉与方法论验收。
你不是作者——请以怀疑的眼光逐条检查，宁可误报不可漏报。

## 交付物
{deck.html 的绝对路径}

## 先读
1. {deck.html} 全文（HTML/CSS/JS）
2. {skill 目录}/references/workflow_qa.md（验收标准：E-01…E-16 + 30 条铁律）
3. {skill 目录}/references/color_and_type.md（配色/字体 token 基准）

## 验收范围（三大块）

### A. 方法论验收（对照 E-01…E-16 与铁律）
- 横向逻辑：只读每页 action title，30 秒内能讲出完整论证吗？（写出你读到的故事线）
- 纵向逻辑：逐页遮住标题看正文，能反推出标题吗？
- 一页一信息；标题是否含两个结论？
- 数字一致性：同一数字在标题/图/文/takeaway 是否完全一致？
  瀑布贡献和 = 起止差？百分比 vs 百分点（pp）是否混淆？
- 每个数字有 Source 吗？格式全篇统一吗？
- 图表规范：排序/零基线/直接标注/语义色角色一致/无 3D/无双轴滥用/预测虚线？
- Sticker 与实际数据状态一致吗？

### B. 视觉验收
- 布局：每页有无内容溢出/遮挡/被截断？（逐页报告）
- 字号层级是否按 visual_spec？标题是否全页最大？
- 对齐与等距：同层元素是否对齐？有无"差 2mm"式瑕疵？
- 对比度：正文/脚注/灰字 vs 背景是否可读？
- 黑白推演：红绿处是否有符号/文字兜底？
- 中英文排版：行距、标题长度（实际两行内）、数字字体是否统一？
- 图表渲染：每个图表是否有数据、轴标签完整、无空白区域？

### C. 工程验收
- 依赖模式是否准确？CDN入口不等于离线自包含；离线模式必须保留关键图表证据，不只是提示失败。
- 演示功能：翻页/全屏/总览/深链/打印逻辑正确吗？
- **强制冒烟测试**：用 headless Chrome 实际打开文件，逐页检查
  （`--headless --dump-dom file://...` 与 `--screenshot` / `--print-to-pdf`）：
  ① 逐页翻页后每个图表 SVG/canvas的显示尺寸与容器一致（canvas另考虑设备像素比）（隐藏容器 init 会产生 100×100 画布——白板病因）；
  ② 打印 PDF 页数 = 幻灯片数；③ console 无错误、无死链接、无无效 JS。
- 断网场景：表格与框架图（SVG/CSS）是否不依赖任何 CDN？

## 输出
写入 {路径}/qa_report.md：
1. 总评：通过 / 有条件通过 / 不通过
2. 发现清单：每条 = 页号 + 严重级（Blocking/Major/Minor）+ 现象 + 依据规则编号 + 修复建议
3. Blocking 项清单（不通过时必有）
```

---

## 编排纪律（主会话）

1. 调研代理、页面设计代理可以并行；QA 代理必须在制作完全结束后单独派出。
2. 子代理返回后主会话必须**抽查**：调研数字 vs 来源、页面规格 vs ghost deck 标题、QA 发现 vs 实际文件。
3. 子代理是 first-year analyst：快但会过度热情、缺纪律——主会话保留 storyline 与最终裁决权。
4. QA 发现 Blocking → 修复 → **重新派发 QA 代理复验**（可复用模板 C，附上一轮报告）。
5. 全部过程文件（brief/ghost_deck/page_plan/page_specs/qa_report/research_notes）落盘
   {输出目录}，随 deck.html 一起交付给用户供迭代。

## v2补充（覆盖旧模板的固定评论列/字数/单图惯例）

页面代理先读 `references/evidence_design.md`、`references/exhibit_system.md`，填写证据ID、几何编码、模块关系和版面预算。QA代理必须实际查看每页原尺寸截图、总览和打印；分别报告证据、视觉、工程状态及5维评分。不允许以代码检查/像素占比代替看图。未看图=视觉未验收；Major也必须整改，禁止仅消除Blocking后即称通过。

## v3主题一致性契约

接收并继承brief中的theme_id/theme_version/selection_basis/overrides和实体→cat索引登记，不自行重选主题。
CSS、ECharts series/visualMap、SVG、表格、状态列必须来自同一assets/deck-themes.js预设。
检查数学正负不误用经营好坏；BCG品牌绿不自动表示达标；Accenture渐变不编码类别。
验收实际fill/stroke、文字反差≥4.5:1、灰度直接标签、打印色阶及图例上下限。
切换主题后必须重建静态图并产生新截图/PDF；仅CSS换色不算通过。

## v4分析表达

设计与QA代理读取 `references/analysis_exhibits.md`。在页面规格中写出关键比较、注释公式、总量/份额标签和过密回退；表格列单位与数据条量尺、流程关系含义同样明确。
QA独立检查注释计算、窄片标签、缺失值和普通表格反例，不把“更多图表”或“更像think-cell”当作质量结论。
