# 内置丰富选型与 planner 解耦：实施与验证

日期：2026-09-18。基线为 `baseline.json` 记录的 Git commit。本轮直接修改实际技能源目录；没有提交、发布、制作安装副本或覆盖用户独立 planner。

## 目标与完成状态

用户要求准确且丰富地使用图表，并明确要求融入所提供的 charts.md、精简 planner。现已将内容选型作为主技能 S3 的默认步骤，保留广泛候选及适用条件，移除常规选型对独立 planner 的加载、快照与有限能力映射依赖。复杂取舍仍可显式使用本地独立 planner，已采纳结果的数据及版本核验继续生效。

## 实际改动

- 新 `references/charts.md` 完整保留原文件 A–M 的 13 类、157 个候选条目，另衔接当前技能的机制、依赖与定性图示。条目包含重复及复合表达，不是 157 种互不重复的原生图表。来源路径与 SHA-256 见 `baseline.json`，来源文件未修改。
- 默认决策为“内容与读者任务 → 关系类别 → 数据和媒介资格 → 候选取舍 → 实现”。没有组件封装不构成放弃合适图型的理由，允许原生 ECharts 与手写 SVG；静态阅读、比较精度、缺失值、口径、证据和来源要求保持。
- `form` 保留为真实实现入口，`visual` 表示实际图型；通用 SVG 页及区域必须声明它，页与主区保持一致，并与成稿 `data-visual` 对账。重复审计按实际表达计数，ECDF、森林图和转移矩阵不会因都用 `svg.custom` 而被算成同一种。审计依赖作者如实命名，不能自动判断图义或识别乱起别名。
- `sweep_forms.cjs` 只读 33 个本地实现入口，不再加载外部 catalog、计算封闭能力覆盖或用能力 ID 阻止自定义图。入口数量不是图型上限。
- planner 改为可选专家；加载器仅读已有本地资源。删除随包快照、锁文件、打包脚本及同步安装脚本，取消自动解包和缓存维护。未使用时 task 可省略 planner，沿用现有 direct 归一化；实际采用时继续核对真实资源、plan、输入文件和摘要、schema 及可见关系，缺失不能改填 direct。
- 更新 SKILL、README、页面创作、展品、交付、分派和 QA 文档，并更新工作区 AGENTS.md 的现行项目事实。未改写主题、字体、引擎底座或旧报告。

## 验证中发现并处理的问题

1. 独立实现审查发现 `svg.custom` 原本仍可省略实际图型，以及页／主区声明可相互冲突。现已补齐拒绝逻辑、成稿对账与反例测试。
2. 独立选型指出留存队列中的“尚未观察”不能被热力组件转换为零。现已在组件入口和实现说明标明有限数值边界，要求缺失状态采用明确编码的自定义 SVG／HTML。
3. 真实样张的连续色阶在 PDF 检查中触发 Canvas 类型错误。定位为 PDF.js 内部默认画布与主画布解析到不同版本的 `@napi-rs/canvas`，不是图型或透明度不受支持。两个 PDF 读取入口现共用同一画布工厂；新增真实 PDF 渐变／透明叠加像素验证，旧有一律禁止透明度的文档限制改为按数据语义使用并核对实际 PDF。没有更换依赖版本，也没有将无锚点精度状态放宽为 PASS。

| 随包 planner Markdown | 87,980 | 0 |

合计指导文本减少 28.45%。主技能自身净增加 6,477 字节：这是按用户要求，把原来依赖外部读取的广泛候选及资格条件内置的明确取舍；没有为满足体积数字删减候选。减法门槛按随主技能分发的指导文本整体已满足；若只看主技能 references，本轮属于有理由的增长，不能宣称每一层都缩短。随包文本并非旧流程每次都会全部读取，以上也不是实测 token 或耗时节省。

## 实际边界

- 157 个候选条目是选型知识覆盖；只有三类完成本轮真实样张验证，没有声称全部已实现、已测试或所有材料都能稳定选对。
- 没有图型配额。准确性和读者任务决定使用哪些图；适合可视化的关系应主动展开，不能用省事或组件缺失压缩为重复摘要。
- 原已生成的历史报告保持不变；旧 `svg.custom` 底稿重新装配时需要补真实 `visual`，不会猜填迁移。
- 不改默认主题、字体或引擎示例，未跑无关全库回归。维护样张没有正式报告交付包装，也不作为整页美学新基线。
- 临时测试目录与本轮 PDF 诊断中间文件已清理，保留可复现输入、脚本、最终样张与检查记录。
